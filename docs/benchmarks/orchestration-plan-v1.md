# Orchestration plan benchmark v1

아래 합성 상황만 사용해 실행 계획을 작성하라. 웹/워크스페이스 검색, 문서 생성·수정, 실제 명령 실행, 권한 변경은 하지 마라. 이미 실행했거나 검증했다고 주장하지 마라.

목표:
- 로컬 오케스트레이터는 요청 분해, 모델 선택, 로컬 파일 적용 및 테스트를 수행한다.
- 비단문 분석과 코드 산출은 외부 AI 데스크톱 앱의 독립 채팅들에 위임한다.
- AI는 개인 인증된 읽기 전용 MCP로 허용된 프로젝트 소스와 지침을 조회한다.
- 모델 추론은 최대 2~3개 동시 진행하지만 화면 조작은 직렬 처리한다.

현재 구현:
- 읽기 전용 broker의 경로/파일 제한, 인증, 출력 한도와 합성 로컬 HTTP 테스트가 있다.
- 모델 metadata 검증과 task/attempt/tab/thread/prompt hash를 대조하는 세션 상태 기계가 있다.
- JSON 전달 CLI와 덮어쓰지 않는 checkpoint, 중복 전송 방지, pause/recovery가 있다.
- UI 어댑터는 fixture 테스트만 통과했다. 실제 모델 메뉴, 고유 채팅 ID, 코드 원문 회수 및 실행 연결은 미완료다.
- 원격 tunnel과 개인 OAuth 연결은 미생성이다. 새 접근 권한과 credential 입력에는 사용자 개입이 필요하다.
- 최근 관측에서는 AI 창 제목과 실제 문서/접근성 정보가 불일치했다. 클릭 반환만으로 전송 성공을 판단할 수 없다.

요청:
1. 가장 먼저 해결해야 할 3개 위험을 근거와 함께 제시하라.
2. 의존 순서에 따른 최대 6개 단계와 단계별 완료 증거를 제시하라.
3. 로컬 테스트, 실제 UI 실행, 개인 원격 인증, 직접 E2E 증거를 구분하라.
4. 다음 상황의 처리 규칙을 짧게 제시하라: 전송 직후 crash, 다른 문서로 전환, 부분 응답, 모델/추론 레벨 변경, 인증 실패.
5. 진행 가능한 로컬 작업과 사용자 승인 없이는 진행하면 안 되는 작업을 구분하라.

모델 계열명만으로 전문 분야 강점을 단정하지 말고, 데이터를 노출하거나 권한을 약화하는 우회를 제안하지 마라. 한국어 900자 이내로 작성하고 마지막 줄을 `ORCH_PLAN_V1_DONE`으로 끝내라.
