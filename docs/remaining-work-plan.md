## 최종 목표

Codex는 작업 분해·로컬 적용·명령·Git·검증을, Notion AI는 독립된 채팅에서 분석·코드 제안을 맡는다. 사용자 승인에 따라 앱과 브라우저 UI를 사용할 수 있다. Notion AI는 개인 인증을 거친 읽기 전용 MCP로 프로젝트와 제한된 Codex 지침을 조회한다.

전체 완료에는 실제 병렬 호출, 분야별 라우팅 근거, 결과 원문 회수, 로컬 적용·테스트 및 중단 복구의 직접 증거가 필요하다. 현재 모든 비단문 요청을 강제 위임하는 자동 실행기는 없다. 기존 미완료 Goal을 로컬 테스트나 연결 성공만으로 완료 처리하지 않는다.

## 남은 실행 순서

| 단계 | 작업 | 완료 증거 |
|---|---|---|
| R1. 실제 UI 연결 | 기존 어댑터와 JSON CLI 연결. 관측한 실제 탭/채팅 ID와 모델·effort·prompt hash 결합 | 별도 채팅의 전송·완료를 정확히 연결하고 사용자 초안/기존 생성을 보호 |
| R2. 원문 회수 | 코드의 공백·줄바꿈·중복 줄·펜스를 보존하고 잘림을 탐지 | 동일 코드 원문 대조. UI가 공백을 정규화하면 완료 주장 금지 |
| R3. 병렬 벤치마크 | 먼저 대표 모델 2개에 동일 비민감 prompt/context. 이후 분석·코딩 과제로 확대 | 실제 선택/effort, 시작·완료 시각, 동일 hash, 원문, 검증 결과 |
| R4. 운영 루프 | 검토된 Notion 산출물의 로컬 적용·테스트와 관측 기반 복구 | 실제 요청→추론→로컬 검증→오류 반환 및 재시작 복구 E2E |
| R5. 운영 보강 | 승인 범위 내 타 계정/폐기 후 거부, 롤백 및 자동 시작 검토 | 각 항목을 별도 확인. 현재 foreground 실행을 상시 서비스라고 보고하지 않음 |

UI 조작은 한 담당자만 수행하고 모델 추론만 2~3개 동시 진행한다. 모델별 speed/intelligence/cost는 후보 선택 근거일 뿐 코딩·분석 전문성의 증거가 아니다. [동일 계획 요청문](benchmarks/orchestration-plan-v1.md)을 시작점으로 사용한다.

## 유지할 경계와 중단 조건

- 인증·Host·경로/링크·credential 제외를 완화해 연결을 통과시키지 않는다. 연결 재생성과 다른 서비스 변경은 하지 않는다.
- 먼저 manifest를 새로 읽고 실제 루트/모드를 확인한다. `/project`는 입력 별칭이 아니며 모든 파일 경로는 상대 경로다.
- `.codex`는 전역 지침과 allowlist 스킬 entrypoint만 읽는다. 도구·권한·대화·참고자료가 자동 복제되는 것은 아니다.
- 사용자 초안/작업 전환/활성 생성, 대상 불일치, 불명확 전송이 발견되면 입력을 멈춘다. 불확실성을 미전송으로 바꿔 자동 재시도하지 않는다.
- 전송 전 checkpoint와 전체 prompt readback, 전송 후 실제 UI 증거를 확인한다. `complete/stable/source` 값 자체는 UI 증거가 아니다.
- 복구 전 기존 UI 담당자의 종료/제어 회수를 확인하고 관측 기반 reconcile을 수행한다. timeout이나 오래된 파일만으로 재전송하지 않는다.
- token·세션 원문·실제 연결 식별정보는 비공개 로컬 자료로 유지한다. 공개 증거에는 결과와 제한만 기록한다.
- 추가 Notion 문서 쓰기/공유, credential 발급/폐기, 재부팅 자동 시작 등록은 해당 범위의 별도 승인이 필요하다.
